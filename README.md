# ObjectTreeDemo

Демонстрация дерева объектов Qt и автоматического удаления виджетов.

## Описание

В приложении показаны:
- владение объектами через родителя;
- автоматическое уничтожение дочерних виджетов при удалении родителя;
- перенос виджета между родителями через `setParent()`;
- демонстрация `setParent(nullptr)` и `deleteLater()`;
- использование `QPointer` для защиты от висячих указателей.

### Теоретическое обоснование

Почти все классы Qt наследуются от `QObject`. Объект может иметь одного родителя и несколько дочерних объектов. Родитель владеет детьми и автоматически удаляет их при своём уничтожении. Так формируется дерево объектов.

`QWidget` дополняет эту модель визуальной иерархией: родитель виджета определяет контейнер, координатную систему и участие в отображении. Вызов `setParent()` меняет владельца и визуального родителя. После `setParent(nullptr)` объект становится независимым, поэтому его удаление нужно организовать отдельно.

`delete` уничтожает объект немедленно. `deleteLater()` планирует удаление через цикл событий Qt и предпочтителен при работе с сигналами и слотами. `QPointer` автоматически обнуляется при уничтожении отслеживаемого объекта и помогает не обращаться к уже удалённому виджету.

### Листинг кода

Точка входа создаёт `QApplication`, показывает главное окно и запускает цикл событий:

```cpp
#include <QApplication>
#include "mainwindow.h"

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);
    MainWindow window;
    window.show();
    return app.exec();
}
```

Главное окно использует `QPointer` для виджетов, срок жизни которых может зависеть от других объектов:

```cpp
class MainWindow : public QWidget
{
    Q_OBJECT
public:
    explicit MainWindow(QWidget *parent = nullptr);
    ~MainWindow() override;

private slots:
    void moveMovableWidget();
    void deletePanel();
    void demoDetaching();

private:
    void setupUi();
    void setStatus(const QString &text);

    QPointer<QVBoxLayout> m_rootLayout;
    QPointer<QVBoxLayout> m_panelLayout;
    QPointer<LogLabel> m_title;
    QPointer<LogLineEdit> m_input;
    QPointer<LogLabel> m_status;
    QPointer<LogPanel> m_panel;
    QPointer<LogButton> m_movable;
    QPointer<LogButton> m_moveButton;
    QPointer<LogButton> m_deleteButton;
};
```

В `setupUi()` создаются дочерние виджеты и раскладки. Кнопка-потомок панели может быть перемещена в главное окно, а затем панель удаляется отложенно:

```cpp
m_panel = new LogPanel("Панель-владелец", this);
m_rootLayout->addWidget(m_panel.data());

m_panelLayout = new QVBoxLayout(m_panel.data());
auto *staticButton = new LogButton(
    "Статическая кнопка внутри панели", m_panel.data());
m_panelLayout->addWidget(staticButton);

m_movable = new LogButton("Перемещаемый виджет (в панели)", m_panel.data());
m_panelLayout->addWidget(m_movable.data());

// Перенос между раскладками: сначала убрать из старой,
// затем сменить родителя и добавить в новую.
m_panelLayout->removeWidget(m_movable.data());
m_movable->setParent(this);
m_rootLayout->addWidget(m_movable.data());

// Удаление панели и оставшихся дочерних виджетов через цикл событий.
m_panel->deleteLater();
```

Полные реализации находятся в [mainwindow.cpp](./mainwindow.cpp), [mainwindow.h](./mainwindow.h) и [widgets.h](./widgets.h). Производные классы виджетов выводят сообщения о создании и уничтожении через `qDebug()`.

### Разбор ошибок и решений

1. **Стековый объект назначен ребёнком кучного родителя.** При уничтожении родитель попытается удалить объект, который автоматически уничтожится при выходе из области видимости. Решение: создавать ребёнка в куче с родителем либо использовать согласованное время жизни объектов.
2. **После `setParent(nullptr)` потерян владелец объекта.** Объект может остаться в памяти. Решение: назначить нового владельца или вызвать `deleteLater()`.
3. **Используется указатель на ребёнка после удаления родителя.** Он становится недействительным. Решение: хранить такой указатель в `QPointer` и проверять его перед использованием.

## Ответы на контрольные вопросы

1. **Что такое дерево объектов QObject?** Иерархия объектов, где у каждого объекта может быть один родитель и несколько детей.
2. **Кто владеет дочерним объектом?** Его родитель `QObject`, который удаляет ребёнка при собственном уничтожении.
3. **Что произойдёт при удалении родителя?** Qt автоматически удалит всех его дочерних объектов.
4. **Чем QWidget-дерево отличается от QObject-дерева?** `QWidget`-дерево дополнительно задаёт визуальное вложение, координаты и отображение виджетов.
5. **Зачем передавать parent в конструктор виджета?** Чтобы сразу установить владельца и, для виджета, визуальный контейнер.
6. **Что делает setParent()?** Меняет родителя объекта; у виджета также меняется визуальный родитель.
7. **Что произойдёт при вызове setParent(nullptr)?** Объект станет без родителя; его дальнейшее удаление нужно обеспечить самостоятельно.
8. **Можно ли вручную удалять объект, у которого есть родитель?** Да, но после удаления нельзя использовать указатели на него; обычно удобнее оставить удаление родителю.
9. **Почему опасно удалять объект через delete внутри обработчика его собственного сигнала?** Объект может быть ещё задействован в текущей обработке сигнала, что приводит к ошибкам или аварийному завершению.
10. **Чем deleteLater() отличается от delete?** `delete` удаляет объект немедленно, а `deleteLater()` планирует удаление через цикл событий.
11. **Что такое висячий указатель?** Указатель на уже уничтоженный объект.
12. **Как QPointer помогает избежать работы с удалённым объектом?** Он автоматически становится `nullptr`, когда объект уничтожается; перед использованием проверяют указатель.
13. **Почему стековый объект нельзя делать ребёнком кучного родителя?** Родитель попытается удалить его, хотя C++ сам уничтожит стековый объект при выходе из области видимости.
14. **Как правильно перемещать виджет из одного layout в другой?** Удалить из старого layout, вызвать `setParent()`, добавить в новый layout и показать виджет.
15. **Что произойдёт, если удалить родителя, а затем обратиться к указателю на ребёнка?** Указатель будет недействителен; обращение к нему приводит к неопределённому поведению.
16. **Как отследить момент уничтожения объекта через деструктор?** Переопределить деструктор и вывести сообщение, например через `qDebug()`.
17. **Почему порядок вызова деструкторов родителя и детей может быть неочевидным?** Тело деструктора родителя выполняется до уничтожения его базовых классов, а дети удаляются позднее в деструкторе `QObject`.
18. **Что возвращает children() у QObject?** Список непосредственных дочерних объектов типа `QObject*`.
19. **Чем findChildren<QWidget*>() отличается от children()?** Он ищет дочерние виджеты заданного типа, по умолчанию включая потомков на всех уровнях; `children()` возвращает только непосредственных детей.
20. **Можно ли иметь у объекта несколько родителей?** Нет, у `QObject` может быть только один родитель.
21. **Как связано дерево объектов и цикл событий Qt?** `deleteLater()` использует цикл событий для отложенного удаления; родительское дерево при этом управляет временем жизни объектов.
22. **Почему для GUI-приложения нужен QApplication и app.exec()?** `QApplication` настраивает GUI-среду, а `app.exec()` запускает цикл событий для окон, сигналов и перерисовки.
23. **Что произойдёт, если попытаться сделать родителем объект из другого потока?** `QObject::setParent()` не выполнит такое изменение и выдаст предупреждение о разных потоках.
24. **Как проверить отсутствие утечек памяти?** Использовать инструменты вроде AddressSanitizer или Valgrind и проверять, что объекты с родителями удаляются вместе с ними.
25. **Почему в данной работе используется QPointer, а не обычные указатели?** `QPointer` безопасно обнуляется при уничтожении `QObject`-объекта, помогая обнаруживать уже удалённые виджеты.
